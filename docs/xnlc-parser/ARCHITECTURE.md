# Предлагаемая архитектура XNLC Parser

Статус: проектное предложение; аудит и проверка реализуемости не завершены. Код библиотеки не написан.

## Границы

Самостоятельный пакет `@xnlc/parser`, TypeScript под Bun, без Rust/WASM/FFI и обёрток над конкурентами. Чистый домен не зависит от SQLite, UI и worker. Интеграционный адаптер в Electrobun преобразует результат к действующим типам, включая data URL, а также сохраняет обработку каталогов и прежний fallback до прохождения регрессии.

## Конвейер

1. `Source`: ограниченный random access для файла и `Uint8Array`, владение ресурсом и отмена. SHA-1 вычислять потоком по запросу.
2. `ArchiveContext`: один раз индексировать центральный каталог, проверить диапазоны смещений, имена, дубликаты, число записей, размер и формат; открыть только нужную запись. Не читать класс или иконку ради обнаружения.
3. `Probe`: собрать все sentinel-файлы, не теряя dual-loader, и признаки ресурсов/шейдеров. Выбор основного представления — явная политика совместимости.
4. `Metadata`: из ограниченных записей получить raw и нормализованные данные; ошибки одного формата возвращать как диагностику, а не скрывать. Не подставлять отсутствующие ID/версии.
5. `Dependency`: сохранить исходное выражение с источником; отдельный слой интерпретации реализует специфичные для загрузчика версии, `any`/`all`, `unless`, optional, side и ordering. Не представлять неизвестное условие как удовлетворённое. Связать nested JAR по metadata ID/версии, а имя считать только подсказкой.
6. `Analysis`: class/mixin и анализ набора включаются по запросу; результат должен описывать пропуски и неполноту. Один контекст переиспользуется всеми запрошенными операциями и закрывается вызывающим через `finally`.

## API и данные

Предложение: `open(source, { limits, signal })` возвращает объект с `identify`, `metadata`, `dependencies`, `classes`, `mixins`, `icon`, `close`; `analyze` — удобный одноразовый вызов, `analyzeBatch` — ограниченная очередь независимых результатов. Результат содержит массив обнаруженных форматов и модов, raw metadata, происхождение и достоверность side, диагностики, вложенные архивы; отдельный batch graph не смешивается с анализом JAR. Неизвестные версии и условия — `unknown`, а не ложный успех. Ошибки имеют код, путь записи и причину без бинарных данных; нарушение общих лимитов останавливает архив, ошибка необязательной иконки не уничтожает metadata. Политика отмены явно проверяется между чтениями и распаковками.

## Безопасность и ресурсы

Лимитировать размер исходника, число записей, каталог, реальную распаковку записи и суммарную распаковку, иконку, metadata, число/глубину/суммарный размер вложений, параллелизм и размер класса. Проверять локальный заголовок и центральный каталог, методы, шифрование, CRC и фактическую длину; отклонять неоднозначные и опасные пути и дубликаты согласно документированной политике. Не доверять одним заявленным размерам или коэффициенту сжатия. ZIP64 реализовать с безопасной проверкой диапазонов либо явно отклонять; не заявлять поддержку до тестов. Потоковый DEFLATE с ограничением вывода нужен для защиты от бомб; синхронная распаковка всего содержимого с проверкой после неё недостаточна. Точный Bun API и семантику ограничения следует проверить экспериментально до выбора реализации.

## Class File

Читать big-endian magic/version, constant pool с корректным modified UTF-8, двойными слотами и проверкой всех индексов, затем flags, имя, superclass, interfaces и длины атрибутов. Пропускать поля/методы по проверенным длинам; декодировать class-level visible/invisible annotations и рекурсивные значения с лимитом глубины. Искать Forge `@Mod` и Mixin `value`/`targets`; сохранять неизвестные атрибуты как пропущенные. Не строить JVM и не декодировать инструкции в metadata-only режиме. Эвристики XMCL, зависящие от инструкций, потребуют отдельного этапа и проверки паритета; совпадение mixin targets не является доказанным конфликтом.

## Память, кэш и workers

Контекст ограничен временем операции; кэш — в адаптере приложения, с ключом, совместимым с существующими `path/size/mtime`, версией parser и защитой от изменений файла во время чтения. Размер иконок и кэша ограничить по байтам. Worker не включать автоматически: сначала измерить процесс целиком, копирование/transfer буферов и нагрузку на UI. Проектировать совместимость с текущим протоколом чанков и fallback, не отдавать worker доступ к БД.
