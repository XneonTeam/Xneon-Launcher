# Текущие ограничения

-  Независимый security-аудит и проверка на всех платформах не завершены.
- Single-disk ZIP64 поддерживается в пределах safe integer и настроенных лимитов; шифрование, multi-disk ZIP и методы кроме stored/deflate отклоняются. Не-UTF-8 имена ZIP могут отклоняться. Набор тестов безопасности и fuzz-проверок не исчерпывающий; проверка размера/временных меток не доказывает неизменность файла при их подделке.
- YAML anchors и aliases отклоняются. Один настоящий Paper JAR проверен, но Bukkit, Bungee и Velocity требуют большего набора реальных плагинов; LiteLoader проверен на внешнем fixture, а не на широком наборе модов.
- Необязательный Class File Parser читает структуру классов и аннотации, но не анализирует инструкции байткода, поля и методы и не интегрирован в автоматическое извлечение metadata legacy Forge. ASM-эвристики не реализованы. Legacy JSON разбирается ограниченно.
- Условия Quilt сохраняются в raw; разрешение `unless`, альтернатив, диапазонов версий и графа зависимостей не реализовано. Совпадение ID вложенного JAR само по себе не доказывает выполнение зависимости.
- Для директорий поддерживаются признаки ресурсов/шейдеров и `pack.mcmeta`; парсер определяет путь к иконке, а лаунчер читает сам файл. Проверка символических ссылок не исключает все гонки замены пути.
- `extractIcon` проверяет структуру и размеры контейнера без декодирования пикселей. SVG/BMP/ICO через этот API не поддержаны; слой интеграции читает их через `ArchiveContext` с ограничением размера.
- SHA-1 и CurseForge fingerprint доступны отдельно. Изменение содержимого с сохранением всех проверяемых атрибутов может остаться незамеченным.
- Результаты прошлого испытания интеграционного worker и список файлов без имени сохранены в исходном репозитории, но не относятся к публичному API пакета. Повторяющиеся записи ZIP по-прежнему отклоняются.
- Benchmark в исходном репозитории не измеряет холодный старт и полный объём работы XMCL; преимущества для всех сценариев не доказаны.
- Проверка проводилась на Windows; отдельные проверки Linux/macOS и регрессии на большом реальном наборе ещё необходимы.
- В версии 1.0.0 `ParserWorker` последователен, создаёт новый поток на каждую задачу и требует явного `close()`. `ParserCache` ограничен количеством и приблизительным весом записей, объединяет одинаковые одновременные запросы и использует размер/mtime/ctime вместо криптографической проверки содержимого. Ни worker, ни кэш не являются постоянным хранилищем.
