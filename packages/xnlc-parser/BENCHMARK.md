# Предварительное измерение metadata

Замеры ниже относятся к прежним версиям. Структурная проверка metadata и новый весовой кэш требуют нового замера; прежние цифры не подтверждают их производительность.

## Повтор после аудита ZIP и самостоятельности пакета

Тот же набор 50 сборок, 3 212 вхождений, три отдельных последовательных процесса XNLC; [сырые значения](benchmarks/audit-after-summary.json). Медиана до изменений — 22,79 с и 135,3 МиБ, после — 13,78 с и 142,0 МиБ. Сравниваемые ID/версии и JSON Fabric/Quilt совпали, число файлов с диагностикой — 22. Прогоны не чередовались, кэш ОС и прочая нагрузка не контролировались: разницу нельзя приписывать ZIP-проверке или считать доказанным ускорением; новый набор проверок усиливает безопасность, а не заявляет оптимизацию.

Диагностический [профиль этапов](benchmarks/audit-phase-profile.json) выполнен на первых 30 различных JAR из манифеста; nested, cache и worker — на первых десяти. Индексация: 40,85 мс; индексация и чтение metadata с DEFLATE/CRC: 87,24 мс; полный `analyze`: 96,97 мс; SHA-1: 53,75 мс; fingerprint: 187,40 мс; 171 консервативная оценка зависимости: 0,23 мс; nested-анализ: 48,89 мс; первый проход кэша: 33,28 мс, повтор: 1,69 мс; последовательный отдельный worker на десять файлов: 275,37 мс. CRC32 отдельно измерен на 100 блоках по 1 МиБ: 2,86 мс. Это одно наблюдение без контроля кэша, этапы отличаются по входам и не складываются в итоговый сценарий. DEFLATE отдельно от файлового I/O и CRC не выделен; чистый overhead worker без самого анализа не измерен. На основании этих данных backend ZIP и `node:zlib` не менялись.

После добавления проверки data descriptor и освобождения индекса при закрытии ещё один проход тех же 3 212 вхождений занял 18,32 с с peak RSS 143,6 МиБ, без новых расхождений в сравниваемых полях и с прежними 22 файлами с диагностикой. [Результаты по сборкам](benchmarks/audit-final-summary.json). Это одиночный контроль, а не оценка влияния этих изменений на производительность.

## Полный проход 50 сборок Modrinth

14 ноября 2026 на Windows 11 x64, i5-13600KF и Bun 1.4.4 протестированы 50 полученных `.mrpack`: 2 433 уникальных JAR из ссылок скачаны с проверкой SHA-1, без ошибок загрузки; у 18 файлов размер отличается от указанного в индексе. В overrides находятся 166 уникальных JAR, из которых 162 отсутствуют в ссылках. После применения приоритета overrides получено 2 595 уникальных файлов и 3 212 вхождений в составах сборок. Из-за тайм-аутов двадцать более высоких позиций поиска заменены следующими доступными проектами: это 50 популярных сборок, но не строгий топ-50. [Манифест](benchmarks/modpacks-50-manifest.json), [отчёт загрузки](benchmarks/modpacks-50-download-report.json), [методика](benchmarks/MODPACKS.md).

Три повтора в отдельных процессах с чередованием порядка; значения в таблице — медианы. Время включает повторное сканирование файлов в каждой сборке; RSS — максимум памяти процесса, включая runtime. Кэш файлов ОС не очищался, пользовательский dev-процесс работал, поэтому результаты не являются холодным запуском и могут зависеть от нагрузки.

| Сценарий | XNLC: время / peak RSS | XMCL 3.4.3: время / peak RSS |
|---|---:|---:|
| Metadata | 22,79 с / 135,3 МиБ | 109,56 с / 245,2 МиБ |
| Metadata + SHA-1 и CurseForge fingerprint | 94,86 с / 168,0 МиБ | 158,29 с / 213,8 МиБ |

В обоих сценариях XMCL запускался в Bun; сравнивались его публичные функции чтения metadata с `analyze` XNLC. Они выполняют неодинаковый объём работы: XNLC дополнительно обнаруживает некоторые форматы и вложения, ASM Forge отключён у обоих. В сценарии хешей **оба** процесса используют один и тот же потоковый код XNLC, поэтому результаты не сравнивают реализации хешей. [Все замеры metadata](benchmarks/modpacks-50-metadata-summary.json), [сравнение результатов по сборкам](benchmarks/modpacks-50-metadata-comparison.json), [все замеры с хешами](benchmarks/modpacks-50-hashes-summary.json), [их сравнение](benchmarks/modpacks-50-hashes-comparison.json).

При каждом повторе одно расхождение: SHA-1 `247d9842ffb5ba27ba88f40b5b44193e0321a523`, JAR с повторяющимися записями классов. XNLC отклоняет неоднозначный архив; XMCL возвращает metadata. У 22 уникальных файлов хотя бы один режим сообщил об ошибке, включая повреждённые TOML и resource metadata; отсутствие расхождения не означает успешного разбора каждого файла. XNLC распознал metadata у 2 584 файлов, XMCL — у 2 585. Для Fabric/Quilt сверялся канонический JSON, включая зависимости; для остальных форматов — загрузчик, ID и версия. Разрешение графа зависимостей и полный анализ байткода не сравнивались.

Отдельный проход XMCL в Node.js 24.16.0 не является полноценным benchmark: десять уникальных файлов получили пятисекундный тайм-аут внутри `readForgeModManifest`, а без тайм-аута процесс завершился с незавершённым ожиданием. [Диагностика](benchmarks/modpacks-50-node-comparison.json), [одиночный запуск](benchmarks/modpacks-50-node-summary.json). Приведённые выше цифры относятся только к основному benchmark metadata и не доказывают превосходство всего лаунчера или полной функциональности XMCL.

В отдельном историческом замере собранный `scan-worker` обработал 3 212 вхождений, с отдельным worker и пустым кэшем для каждой сборки. SHA-1 совпали; в 16 вхождениях (13 уникальных JAR) имя осталось пустым. Обработка согласованных метаданных крупных мультизагрузочных файлов уменьшила число таких вхождений с 19 до 16. [Результаты по сборкам и SHA-1 без имени](benchmarks/modpacks-50-worker-results.json), [до исправления мультизагрузочных метаданных](benchmarks/modpacks-50-worker-before-multiloader.json). Один проход занял 54,09 с с общим peak RSS 433,5 МиБ. Условия отличаются от таблицы выше по объёму работы, параллелизму и модели worker.
